## TL;DR

The Linux hand-off is now **one explicit action after the jailbreak** and it is reliable:

```
Orbis ──[lab "Linux" button, or PayLoader .elf]──► Linux     (no power menu, no evf, no kill(1))
Linux ──[Power off (Orbis) shortcut]────────────► off
off   ──[power button]──────────────────────────► Orbis
```

The payload no longer chains itself to the exploit. It is sent **after** GoldHEN is fully
up, which removed the SceShellCore race that froze the console earlier.

## Root cause of the hand-off problem (confirmed)

`sys_reboot()` on 14.00 never reaches `icc_query_nowait`; only the shell-orchestrated
shutdown (power menu) does. That is why every `evf_cancel` / `evf_set` / `kill(1, SIGUSR1)`
variant failed — and why the power menu worked.

Fix: hook **`kern_reboot`** (kernel base + `0x3A2850`) as well, and call it from kernel
context inside `sys_kexec` (`-DHOOK_KERN_REBOOT -DAUTO_TRIGGER=0x0`). `kern_reboot` is on
every reboot path, so the hand-off depends on nothing in userland.

`AUTO_TRIGGER` is gated on `kern_reboot_hooked`, so a failed hook install degrades instead of
powering the console off.

## Three traps found the hard way

1. **Never chain the POST behind the installer.** Posting `linux-autoboot.bin` in the same
   second `chain exited 0` fires `kern_reboot` while SceShellCore is still restarting →
   hard freeze, no ICMP. The lab now only sends the payload on an explicit press.

2. **Never probe port 9090.** GoldHEN's binloader treats *every accepted TCP connection* as
   an incoming payload. A `socket.create_connection()` health check, or one stray byte from
   `echo > /dev/tcp/.../9090`, is logged as
   `invalid payload format... skipping` and **the binloader exits for that boot**; the real
   POST then gets connection refused. The POST itself is the only safe health check.
   (This cost a whole boot: a 1-byte probe killed the server before the button was pressed.)

3. **The legacy reboot watchdog was a 1-second time bomb.** `main()` started `reboot_thread`
   before `kexec_load()`; that thread sleeps 1 s and runs the old
   `evf_cancel(0x4000)` + `kill(1, SIGUSR1)` — the exact call that wedges 14.00. It only
   mattered when `AUTO_TRIGGER` did not fire, and then it turned "payload did nothing" into a
   dead console. Shipped builds now use `-DNO_REBOOT_WATCHDOG`.
